# 접근성 감사 보고서

## 영향도

| 수준 | 의미 |
| --- | --- |
| CRITICAL | 해당 사용자 흐름을 수행할 수 없음 |
| MAJOR | 수행에 상당한 장벽이 있음 |
| MINOR | 불편 또는 부분적인 개선 필요 |

기준 적용 수준과 실제 사용자 영향을 함께 확인한다. 크기 하나만 보고 영향도를 기계적으로 정하지 않는다. 예를 들어 36dp 대상은 플랫폼 권장보다 작을 수 있지만 AA의 24 CSS px 기준을 위반한다고 단정할 수 없다.

같은 코드도 모바일 화면 낭독, 웹 키보드, 데스크톱 고대비 환경에서 영향이 다를 수 있다. 읽기 불가·조작 불가·가려짐·모션·툴팁·페이지 제목·건너뛰기·색상 문제를 실제 대상 환경에 맞춰 판단한다.

## 보고서 템플릿

```markdown
# 접근성 감사 결과

- 목표: WCAG 2.2 [수준, 선택 AAA ID]
- 플랫폼: [대상]
- 범위: [파일·화면]
- 결과: CRITICAL [N], MAJOR [N], MINOR [N]
- 검증: [소스 검사·자동 테스트·실제 보조 기술 실행 여부]

## 발견 [번호]: [문제]

- 위치: [파일:줄]
- 플랫폼: [영향 대상]
- 기준: [ID, 이름, 수준, 도입 버전]
- 영향도: [CRITICAL / MAJOR / MINOR]
- 문제와 영향: [근거]
- 수정 전 Dart 코드: [해당 코드]
- 수정 후 Dart 코드: [제안 코드]

## 확인한 통과 항목

[검사와 실제 근거]

## 미검증·범위 밖 항목

[실행 환경·색상·실제 읽기 순서 등 확인하지 못한 것]

## 수정 결과

[수정 수, 남은 수, 테스트 결과]
```

## 수준별 통과 목록

A에서는 대체 텍스트·관계·순서·키보드·색 이외 정보·기본 폼·인증 이름/역할 등을 확인한다. AA에서는 대비·확대·리플로·포커스·대상 크기·드래그 대안·상태 메시지 등을 추가한다. AA와 선택 AAA에서는 선택된 ID만, AAA에서는 해당 상위 기준을 추가한다. [기준 표](wcag-criteria.md)에 따라 실제 확인한 항목만 통과로 기록한다.

여러 플랫폼이면 각 발견에 영향을 받은 플랫폼을 쓰고, 같은 코드지만 영향도가 다르면 `CRITICAL (iOS), MAJOR (Web)`처럼 구분한다. 확인했지만 영향 없는 플랫폼도 근거가 필요한 경우 명시한다.
