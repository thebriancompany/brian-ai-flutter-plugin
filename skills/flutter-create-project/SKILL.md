# Dart·Flutter 프로젝트 생성

새 앱·패키지·플러그인·CLI·게임을 템플릿으로 생성하고 의존성을 설치한다. 기존 프로젝트의 작은 변경에는 적용하지 않는다.

공식 권고와 팀 관례의 구분, SDK·언어 버전, 오류·수명 처리는 [공통 기준](../flutter-review/SKILL.md#공식-기준과-프로젝트-관례)을 적용한다.

## 진행 방법

1. 사용자가 만들려는 결과로 템플릿을 판단한다. 도구의 하위 명령 이름을 사용자에게 선택하도록 요구하지 않는다.
2. 프로젝트 이름·출력 위치·필수 조직 식별자를 기존 요청과 저장소에서 확인한다. 정말 모호한 필수 정보만 한 번에 질문한다. 선택적 설명·앱 ID 등을 불필요하게 묻지 않는다.
3. 연결된 생성 MCP가 있으면 실제 스키마의 템플릿·인수를 확인한다. 없으면 `very_good create --help`와 해당 하위 명령의 도움말을 확인하고 CLI를 사용한다.
4. 새 디렉터리에 생성한 뒤 그 디렉터리에서 `very_good packages get` 또는 맞는 pub 명령으로 의존성을 설치한다. 작업 공간 루트와 혼동하지 않는다.

## 템플릿 선택

| 결과 | 템플릿 |
| --- | --- |
| Flutter 앱 | `flutter_app` |
| 순수 Dart 라이브러리·API 클라이언트·저장소 | `dart_package` |
| Flutter SDK를 쓰는 일반 패키지 | `flutter_package` |
| 네이티브 연동 플러그인 | `flutter_plugin` |
| Dart 명령줄 앱 | `dart_cli` |
| Flame 게임 | `flame_game` |
| 문서 사이트 | `docs_site` |
| 공유 위젯·디자인 토큰 UI 패키지 | [UI 패키지 스킬](../flutter-ui-package/SKILL.md)의 `app_ui_package` |

이 표는 very_good_cli를 선택한 경우의 템플릿이다. CLI 버전이 지원하는 템플릿을 확인한다. 기존 도구를 우선하고 기본 골격이면 공식 `flutter create` 또는 `dart create`로도 생성할 수 있다. 사용자가 다른 생성 도구를 명시했다면 그 선택을 따른다.

## 도메인 규칙

- 데이터·저장소는 가능하면 순수 Dart 패키지로 만들되 Flutter 플러그인이 필요하면 Flutter 패키지로 만든다. 계층 분리 자체가 독립 패키지를 강제하지 않는다.
- Dart 패키지 이름의 하이픈은 밑줄로 정규화하고 소문자·숫자·밑줄 규칙을 확인한다.
- 앱·플러그인·게임 템플릿이 조직명을 요구하면 확인된 조직명을 사용한다. 없으면 가짜 식별자를 넣지 말고 묻는다.
- 생성 후 의존성 설치가 실패하면 생성 경로·SDK PATH·solver 출력을 확인한다.
- `very_good` 실행 파일이 없으면 설치 상태를 알리고 설치 명령 `dart pub global activate very_good_cli`를 제시한다. 도구 설치 권한과 환경을 확인하고 수행한다.

MCP 이름이나 호스트 전용 인수 치환은 가정하지 않는다. Codex의 사용 가능한 질문 도구를 쓰고 없으면 일반 텍스트로 질문한다.
