# 의존성 라이선스 검토

Dart·Flutter의 해결된 직접·간접 의존성 라이선스를 확인하고 프로젝트 배포 방식과 정책에 맞춰 보고한다. 자동 스캔만으로 법률 판단이나 배포 적합성을 보증하지 않는다.

공식 권고와 팀 관례의 구분, SDK·언어 버전, 오류·수명 처리는 [공통 기준](../flutter-review/SKILL.md#공식-기준과-프로젝트-관례)을 적용한다.

## 기준

- 패키지 이름이나 pubspec 목록만으로 라이선스를 확정하지 않는다. 해결 버전의 실제 라이선스와 스캔 결과를 사용한다.
- 라이선스를 찾지 못했다고 자유 사용 가능한 것으로 판단하지 않는다. 확인 필요 항목으로 남긴다.
- 허용적인 직접 의존성에도 간접 의존성의 별도 조건이 있다.
- 사용자가 제공한 스캔 결과도 입력으로 분석한다. 분석 범위·버전·누락을 밝히고 불필요하게 재실행을 요구하지 않는다.
- 조직의 허용 목록과 배포·수정·링크 방식을 확인한다. MIT 등도 저작권·허가 고지 조건이 있다.

## 실행

연결된 라이선스 MCP의 실제 스키마를 확인한다. `packages_check_licenses`가 지원되면 `licenses: true`와 대상 `directory`, 직접·간접 의존성을 포함하는 옵션을 지정한다.

MCP가 없으면 설치 CLI의 도움말을 확인한 뒤 `very_good packages check licenses <project-directory> --dependency-type direct-main,transitive`를 사용한다. 경로는 위치 인수이며 작업 공간 루트와 실제 프로젝트를 구분한다. 스캔 실패는 통과가 아니다.

## 분류

| 유형 | 예 | 검토 |
| --- | --- | --- |
| 허용적 | MIT·BSD·Apache-2.0 | 고지·특허·재배포 조건 확인 |
| 약한 카피레프트 | LGPL·MPL | 수정·파일 범위·링크·배포 조건 검토 |
| 강한 카피레프트 | GPL·AGPL | 결합·배포·네트워크 제공 방식에 따른 의무 검토 |
| 미확인 | 누락·인식 불가 | 원문·버전 확인 필요 |

분류만으로 모든 사용에 안전하다거나 전체 앱의 라이선스가 반드시 바뀐다고 단정하지 않는다.

## 보고

다음 한국어 형식으로 총계와 항목별 권고를 제공한다. 검사하지 않은 간접 의존성은 범위 밖으로 명시한다.

```markdown
## 라이선스 검토 결과

### 요약
- 검사한 의존성: N
- 확인한 정책 조건 충족: N
- 검토 필요: N
- 범위: [프로젝트·해결 버전·직접/간접 포함 여부]

### 검토 필요 의존성
| 패키지 | 라이선스 | 검토 우선순위 | 권고 |
| --- | --- | --- | --- |
| package_name | GPL-3.0 | 높음 | 실제 배포 조건 검토 또는 대안 확인 |

### 조건을 확인한 의존성
[근거와 유지할 고지·조건]

### 권고
1. [우선 조치]
2. [후속 조치]
```

패키지별 한 행을 작성한다. 결과가 없는 이름 목록뿐이라면 간접 의존성이 빠졌음을 설명하고 정확한 검사 명령을 제시한다. 실행을 요청받았고 환경이 허용하면 수행한다. 실제 라이선스 정보가 제공되었다면 이를 분석하고 결론의 범위만 제한한다.
